## 3. THE CALCULATOR (the heart of the project, must be the best)

### 3.1 Behaviour
- Homepage loads with the calculator visible **above the fold on mobile and desktop**, with sensible defaults already filled so a result shows immediately (e.g. 70 kg / 154 lb, 3.5 mph, 30 min). Results update live as the user types or drags. Also include a clear "Calculate" button for users who expect one.
- Unit toggle Imperial / Metric (lb, ft+in, mph, miles vs kg, cm, km/h, km). Auto-select default from browser locale, remember the choice.
- Four input modes (tabs or segmented control):
  1. **Time + Speed** (most common). Speed via slider plus presets: Stroll, Casual, Moderate, Brisk, Power walk, Race walk.
  2. **Distance + Time** (calculates pace/speed automatically).
  3. **Steps** (steps + height, or custom stride length; calculates distance, time and calories).
  4. **Treadmill / Incline** (speed + incline % + duration).
- Fields: weight, height (needed for steps and stride), age and sex (optional, used for net calories and daily-percentage context), duration (h/min), speed or pace, incline %, terrain (pavement, trail, sand, grass), optional backpack/load weight.
- Toggle **Gross vs Net calories** (net = excluding resting burn), with a one-line explanation.

### 3.2 Formulas (implement in a pure, unit-tested `lib/calc` module)
- Main: `kcal = MET × weight_kg × hours`.
- Walking MET values (Compendium of Physical Activities, 2011). Use linear interpolation between points. Verify values against the Compendium before shipping and cite it:
  - 2.0 mph (3.2 km/h) = 2.8
  - 2.5 mph (4.0 km/h) = 3.0
  - 3.0 mph (4.8 km/h) = 3.5
  - 3.5 mph (5.6 km/h) = 4.3
  - 4.0 mph (6.4 km/h) = 5.0
  - 4.5 mph (7.2 km/h) = 7.0
  - 5.0 mph (8.0 km/h) = 8.3
- Net calories: `(MET − 1) × weight_kg × hours`.
- Incline/treadmill (and optional load): use the ACSM walking equation. `VO2 (ml/kg/min) = 0.1 × speed(m/min) + 1.8 × speed(m/min) × grade(decimal) + 3.5`, then `kcal/min = VO2 × weight_kg / 1000 × 5`. Valid roughly 1.9 to 3.7 mph; above that, fall back to MET table and add an incline adjustment, and show a small "estimate" note.
- Steps to distance: `stride = height × 0.414` (average; allow manual override). Provide steps per mile/km result.
- Fat/weight context: about 7,700 kcal per kg (3,500 kcal per lb) of body fat, clearly labelled as an approximation.
- Sanity check: 70 kg, 3.5 mph, 1 hour must give about 301 kcal. Write unit tests for this and for edge cases (zero, huge values, unit conversion round-trips). Validate inputs with friendly inline messages, never crash.

### 3.3 Results panel (make it beautiful and useful)
- Big animated number: **total calories burned**, with a ring/progress visual.
- Secondary stats: calories per minute, per mile/km, distance, estimated steps, average pace (min/mile and min/km), net vs gross.
- "What does this equal?" (fat equivalent, simple food equivalents like a banana or slice of pizza, based on common kcal values).
- **Speed comparison chart:** the same duration and weight at different speeds (small SVG bar chart).
- **Weight-loss projection:** "If you walk like this X days/week, about Y per month" with honest wording and an approximation note.
- Actions: Copy result, Share link (inputs in URL params, no personal data stored server-side), Print/Save as PDF-friendly view, Reset.
- Recent calculations saved only in the user's browser (localStorage, wrapped in try/catch).
- Always show a short medical disclaimer link near the result. Estimates only.

### 3.4 UX/UI requirements
- Mobile-first (most traffic will be mobile). Large tap targets, number keyboards on numeric inputs, no horizontal scroll.
- Visual style: modern, clean, friendly health/wellness feel. Fresh green/teal as the main colour, one warm accent (orange) for the primary button, lots of white space, rounded cards, subtle shadows, smooth micro-animations. Include dark mode. Pick one excellent font pair and self-host it.
- Fully accessible (WCAG AA): labels, focus states, keyboard use, aria-live for results.
- Performance targets: Lighthouse 95+ on Performance, Accessibility, Best Practices, SEO on mobile. LCP under 2s, CLS under 0.1, INP good.
- No popups, no interstitials, no autoplay. Nothing that gets in the way of the calculator.
